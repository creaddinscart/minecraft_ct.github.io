Configuration / CT v2.2.0.1

Settings and configuration.

Every non-secret setting lives in ~/.ct-client/settings.properties. Missing keys fall back to defaults, invalid numbers fall back per key, and credentials or access tokens are never part of the file.

Properties file

settings.properties.

A standard Java properties file created automatically when the launcher starts. The CT_MICROSOFT_CLIENT_ID environment variable overrides microsoft.clientId when it is set and not blank.

The Microsoft application must be a public client with the device code flow enabled, allowed to use the XboxLive.signin and offline_access scopes. See accounts.

API

ClientSettings.

com.ct.client.ClientSettings reads and writes the properties file and is also usable from your own code.

  • ClientSettings() — reads ~/.ct-client/settings.properties, creating the application directory and the file when missing. Throws IOException when the file cannot be read.
  • applicationDirectory() — static. ~/.ct-client, absolute and normalized.
  • microsoftClientId() / setMicrosoftClientId(String) — Azure public client ID, overridden by CT_MICROSOFT_CLIENT_ID when set and not blank.
  • gameDirectory() / setGameDirectory(Path) — game directory, defaulting to <application directory>/game.
  • launchOptions() / setLaunchOptions(LaunchOptions) — memory, resolution, and flag settings. Invalid stored values fall back to LaunchOptions.defaults().
  • offlinePlayerName() / setOfflinePlayerName(String) — last used offline name.
  • javaExecutable() / setJavaExecutable(Path) — optional Java executable override. null means the installed official runtime is used.
ClientSettings settings = new ClientSettings();
Path gameDirectory = settings.gameDirectory();
LaunchOptions options = settings.launchOptions();
settings.setOfflinePlayerName("DevPlayer");
API

LaunchOptions.

An immutable record of memory, window, and flag settings. Invalid arguments throw IllegalArgumentException from the constructor.

  • minimumMemoryMb, maximumMemoryMb — heap bounds, between MINIMUM_MEMORY_MB (1024) and MAXIMUM_MEMORY_MB (65536). The maximum must be at least the minimum.
  • customResolution, width, height — when enabled, the resolution must be at least 320 by 240, and the has_custom_resolution feature is reported to the game.
  • demoMode — reports is_demo_user to the game.
  • recommendedJvmFlags — applies Mojang's default-user-jvm entries before the version arguments.
  • versionType — value of version_type. "release" for a normal install.
  • LaunchOptions.defaults() — 2048/4096 MB, no custom resolution, 854 by 480, recommended flags on, "release".
LaunchOptions options = new LaunchOptions(2048, 4096, false, 854, 480, false, true, "release");
Desktop

What the window persists.

The desktop launcher and the settings file are not fully symmetrical. Knowing which fields round-trip avoids surprises on the next launch.

  • Persisted by the window: the Microsoft client ID and the offline player name.
  • Read from the file: the memory, resolution, game directory, and Java executable fields are read from settings.properties when the window opens, and the launch reads the settings file again, so edits to those four fields in the window do not change the next launch.
  • Workaround: set those four fields in settings.properties, or use the command line flags --game-dir and --memory-max.
  • Launcher version: the version passed to the game is 2.2.0.1, matching the Maven version in pom.xml.
  • Command line limits: headless mode has no Microsoft sign-in and no offline name persistence.
  • Secrets: access tokens are never written to disk and never part of ClientSettings; see security.

Current limitation: edits to memory, resolution, game directory, or Java executable inside the window are not saved. Change them in ~/.ct-client/settings.properties or on the command line.
