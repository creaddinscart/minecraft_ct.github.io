Boundaries

Current limitations

Four limitations are known in CT v4.2.0.

  • Some desktop window fields do not feed the launch. The desktop launcher persists the Microsoft sign-in method, the Microsoft client ID, and the offline player name. The memory, resolution, game directory, and Java executable fields are read from settings.properties when the window opens, and the launch reads the settings file again, so edits to those four fields in the window do not change the next launch. Set them in settings.properties, or use the command line flags.
  • Command line mode has no Microsoft sign-in and no offline name persistence. The CLI always uses an offline profile, and it is not remembered between runs.
  • The launcher version passed to the game is fixed. It is 4.2.0, matching the Maven version in pom.xml.
  • Offline profiles cannot join online-mode servers. The launcher does not retry the player/attributes or Realms endpoints, which reject offline profiles with HTTP 401.
Workaround

For the four window fields, edit settings.properties directly — the launch reads it fresh every time.

Files

Where everything lives

All CT files sit under one hidden application directory, ~/.ct-client.

~/.ct-client/
  settings.properties          Non-secret launcher settings
  game/
    versions/<id>/<id>.json    Verified official version metadata
    versions/<id>/<id>.jar     Verified client jar
    versions/<id>/natives/     Natives subdirectories referenced by the metadata
    libraries/                 Rule-matched libraries, including natives classifiers
    assets/indexes/            Asset index
    assets/objects/            Asset objects, stored under their SHA-1 prefix
    assets/log_configs/        Official log4j configuration
    runtimes/                  Official Java runtime, with the completion marker
    logs/ct-client-launch.log  Streamed game output, appended per launch

Mod JARs go one level further, in ~/.ct-client/game/mods/ — see how to open the mods folder.

Custom path

The game.directory key moves the whole game/ tree; settings.properties always stays in ~/.ct-client.

Quick answers

Frequently asked

MODS

Where do Fabric mods go?

Fabric mods go in the same mods/ folder — CT detects fabric.mod.json and hands off to the matching Fabric profile automatically.

SERVERS

Can offline profiles join servers?

Only servers that explicitly disable authentication. Online-mode servers reject offline profiles with HTTP 401.

SETTINGS

Where are my settings?

In ~/.ct-client/settings.properties. Tokens are never written there — a sign-in lasts for the current session only.

WINDOW

Why did my window edits not apply?

The memory, resolution, game directory, and Java executable fields in the window are read-only for the launch. Edit the settings file instead.
