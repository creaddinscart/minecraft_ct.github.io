CT v4.0.0 / modular platform

One main program. Every feature is a module.

CT-Main ships with nothing but the welcome window. Every feature — installer, launcher, accounts, console, mods — is a separate module jar you download once and drop into the modules folder.

How it works

Installing a module

CT-Main scans its modules folder on every start. The default folder is ~/.ct-client/modules; when CT-Main.jar sits next to a modules folder, that folder is used instead.

  1. 1

    Download CT-Main

    Get CT-Main-4.0.0.jar from the release page and start it:

    java -jar CT-Main-4.0.0.jar

    You see the welcome window and nothing else — exactly what the main program is: a module host.

  2. 2

    Download the modules you want

    Each module is a single jar listed below. A module only loads when every module it requires is present, so the simplest full setup is: download all of them.

  3. 3

    Drop the jars into the modules folder

    mkdir modules
cp ct-module-*-4.0.0.jar modules/
java -jar CT-Main-4.0.0.jar

    The console lists what loaded and what was skipped, with the reason. A different folder can be passed with --modules-dir <path>.

Load order and services

Modules load in dependency order: a module that requires another module always initializes after it. Modules publish services to each other — the settings module publishes the settings store, the installer module publishes the game installer, and the launcher builds on both. If a required module is missing or fails, the depending module is skipped with a reason in the console, and CT-Main keeps running with the rest.

Minimal setups: only settings + installer + versions + launcher is enough to install and launch the game. Add account-offline or account-microsoft for accounts, console to watch the output, and modman plus ctloader to manage and load mods.

Modules are plain jars with a ct.module.json manifest. Writing your own is documented on the API page; CT-Main loads any jar that follows the same manifest format.
