Release notes / CT v1.0.0

CT Loader foundation

The game process now enters through CT, giving the project its first native mod discovery and initialization path.

Game Minecraft Java 26.3Format CT mod schema 1Status Foundation

Added

  • An in-process CT bootstrap that runs before the official Minecraft main class.
  • CT mod discovery from the configured game directory's mods/ folder.
  • A metadata contract using ct.mod.json, mod IDs, versions, entrypoints, and required dependencies.
  • Dependency-first ordering and validation for duplicate IDs, missing dependencies, and cycles.
  • A Java entrypoint API with access to the game directory, mods directory, mod metadata, and scoped logging.
  • Dependency and initialization tests as part of the Maven test lifecycle.

How launch changed

The launcher still installs and verifies official Minecraft files. It now appends its own application JAR to the game classpath and selects CTLoaderBootstrap as the process entrypoint. CT initializes discovered CT mods, then invokes Minecraft's official main class with the original game arguments.

This keeps the existing account, runtime, and official metadata flow while adding a clear CT-owned boundary for mod loading.

Not included yet

  • No Fabric, Forge, or NeoForge compatibility.
  • No Minecraft class transformation or game lifecycle/event hooks.
  • No sandbox: a mod JAR executes Java code with the same permissions as CT.

Honest status: the current entrypoint runs before Minecraft initialization. The API is a loader foundation; it does not by itself let a mod change Minecraft gameplay.

Build and verify

./mvnw package

The package command runs the loader tests and produces target/ct-client-1.0.0.jar.
