CT Loader / mods

Mods

CT Loader looks for mod JARs in the mods directory inside the configured game directory, checks their required dependencies, and invokes their initialization entrypoints on launch.

Start here

How to open the mods folder

The mods folder is always <game directory>/mods/. With the default settings the game directory is ~/.ct-client/game, so the full default path is ~/.ct-client/game/mods/.

Expanded on each platform:

PlatformDefault mods folder
macOS/Users/<name>/.ct-client/game/mods
Windows%USERPROFILE%\.ct-client\game\mods
Linux/home/<name>/.ct-client/game/mods

~/.ct-client is a hidden folder on every platform, because its name begins with a dot on macOS and Linux and Windows treats it as a dot-folder in your home directory. That is why it does not show up in a normal file listing. Each platform has a quick way to reach it:

macOS

Use Finder's Go > Go to Folder (Cmd+Shift+G) and paste the path, or open it straight from Terminal:

open ~/.ct-client/game/mods

You can also reveal the application folder in Finder with open ~/.ct-client, then navigate into game/mods.

Windows

Paste the path directly into the File Explorer address bar and press Enter:

%USERPROFILE%\.ct-client\game\mods

Or open it from Command Prompt or PowerShell:

explorer %USERPROFILE%\.ct-client\game\mods

Linux

Press Ctrl+L in your file manager and type the path, or open it from a terminal:

xdg-open ~/.ct-client/game/mods

Custom game directory: if game.directory was changed in the settings, the mods folder is under that directory instead — it is always <game directory>/mods/, never fixed to ~/.ct-client. The command line --game-dir flag changes it for a single run.

CT creates the mods/ directory automatically on launch, so you can also just start CT once and then open the folder. To create it yourself:

mkdir -p ~/.ct-client/game/mods

Place each mod JAR directly inside the folder — CT does not scan subdirectories.

Path rule

Whatever the game directory is set to, mods always live one level down, in mods/ inside it.

Writing a mod

Installing a CT mod

Every CT mod JAR must contain a ct.mod.json file at its root. The first schema supports required dependencies and one or more Java entrypoints.

ct.mod.json, schema 1

{
  "schemaVersion": 1,
  "id": "example",
  "name": "Example Mod",
  "version": "1.0.0",
  "entrypoints": ["example.ExampleMod"],
  "depends": []
}
FieldMeaning
schemaVersionFormat version. 1 is the only schema CT currently reads.
idUnique mod identifier. Duplicate IDs across installed mods are rejected.
name / versionDisplay name and version string.
entrypointsOne or more fully qualified class names to initialize.
dependsOptional array of required CT mod IDs. Each must be installed.

Entrypoint class

An entrypoint is a public class with a public no-argument constructor that implements com.ct.client.loader.CTMod:

package example;

import com.ct.client.loader.CTMod;
import com.ct.client.loader.CTModContext;

public final class ExampleMod implements CTMod {
    @Override
    public void onInitialize(CTModContext context) {
        context.log("Example Mod initialized");
    }
}

Dependencies and validation

The optional depends array contains required CT mod IDs. CT checks that each dependency is installed, rejects duplicate IDs and dependency cycles, and initializes dependencies first. A malformed mod or a failed entrypoint stops launch with an error in the CT output.

Security warning: mods are executable Java code. Only install mod JARs you trust — loading a mod runs its entrypoints with the same privileges as CT and the game.

CT's own mod API provides initialization and logging only; it is separate from Fabric, Forge, and NeoForge APIs and does not yet expose Minecraft game hooks or bytecode transformation.

Launch order

Dependencies initialize before the mods that depend on them, so a dependency is always ready first.

Other loaders

Fabric mod detection

CT detects Fabric mod JARs in the game mods/ folder and routes the launch to an installed Fabric profile automatically.

When a JAR containing fabric.mod.json is present, CT checks the installed profiles and automatically uses the sole installed Fabric profile matching the selected Minecraft version:

  • No matching profile — install Fabric Loader into the same game directory using its official installer, then refresh the profile list. CT reports when Fabric Loader must be installed or a profile selected.
  • Several matching profiles — select one explicitly in the desktop launcher.

CT does not download or repair loader files, and the external loader — not CT's native API — loads its mods. CT installs the profile's required vanilla Minecraft parent version when it is missing, but loader installation and loader-library repair remain the responsibility of that loader's installer. The same handoff covers Forge and NeoForge profiles installed by their own installers. Profile launching is currently desktop-only; the command line interface continues to install and launch vanilla versions.

Security warning: this applies to Fabric mods too — a JAR with fabric.mod.json is still executable Java. Only install JARs you trust.
