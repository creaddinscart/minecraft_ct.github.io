CT mod format / schema 1

Install a CT mod.

CT mod JARs declare metadata and a Java initialization entrypoint. Put the JAR in the active game directory, then launch CT.

Install location

Place each mod JAR directly in <game directory>/mods/. For the default installation, that is:

~/.ct-client/game/mods/

The desktop launcher creates the folder on launch. If you changed the game directory in CT settings, use the mods/ folder under that directory instead.

Declare the mod

Put ct.mod.json at the root of the JAR. The ID must be unique and use lowercase letters, digits, underscores, or hyphens.

{
  "schemaVersion": 1,
  "id": "example",
  "name": "Example Mod",
  "version": "1.0.0",
  "entrypoints": ["example.ExampleMod"],
  "depends": []
}

depends is optional. Every listed ID must be present. CT initializes dependencies before the mod that requires them.

Implement the entrypoint

Each entrypoint class must be public, have a public no-argument constructor, and implement CTMod:

package example;

import com.ct.client.loader.CTMod;
import com.ct.client.loader.CTModContext;

public final class ExampleMod implements CTMod {
    @Override
    public void onInitialize(CTModContext context) {
        context.log("Example Mod initialized");
    }
}

The context exposes the mod metadata, game directory, mods directory, and a logger prefixed with the mod ID.

Compatibility and trust

This is CT's own format. Fabric, Forge, and NeoForge JARs are not compatible. There are no Minecraft class transformation hooks or in-game events yet, so an entrypoint currently runs before Minecraft starts.

Security: mods are ordinary executable Java code, not sandboxed plugins. Only install JARs from sources you trust.
