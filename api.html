Reference / CT v2.2.0.1

Programmatic API.

Every CT class is usable from your own Java code. The desktop launcher and the command line are thin frontends over exactly the interfaces documented here — nothing in them is hidden or private by accident.

ClientSettings

Non-secret settings persisted as a properties file at ~/.ct-client/settings.properties. Credentials and access tokens are never part of it.

ClientSettings settings = new ClientSettings();
Path gameDirectory = settings.gameDirectory();
LaunchOptions options = settings.launchOptions();
settings.setOfflinePlayerName("DevPlayer");
MemberDescription
ClientSettings()Reads ~/.ct-client/settings.properties, creating the application directory and the file when missing. Throws IOException when the file cannot be read.
applicationDirectory()Static. ~/.ct-client, absolute and normalized.
microsoftClientId() / setMicrosoftClientId(String)Azure public client ID. The CT_MICROSOFT_CLIENT_ID environment variable overrides the stored value when it is set and not blank.
gameDirectory() / setGameDirectory(Path)Game directory, defaulting to <application directory>/game.
launchOptions() / setLaunchOptions(LaunchOptions)Memory, resolution, and flag settings. Invalid stored values fall back to LaunchOptions.defaults().
offlinePlayerName() / setOfflinePlayerName(String)Last used offline name.
javaExecutable() / setJavaExecutable(Path)Optional Java executable override. null means the installed official runtime is used.

LaunchOptions

LaunchOptions options = new LaunchOptions(2048, 4096, false, 854, 480, false, true, "release");
FieldDescription
minimumMemoryMb, maximumMemoryMbHeap bounds, between MINIMUM_MEMORY_MB (1024) and MAXIMUM_MEMORY_MB (65536). The maximum must be at least the minimum.
customResolution, width, heightWhen enabled, the resolution must be at least 320 by 240, and the has_custom_resolution feature is reported to the game.

Invalid arguments throw IllegalArgumentException from the record constructor. LaunchOptions.defaults() returns 2048/4096 MB, no custom resolution, 854 by 480, recommended flags on, "release".

Account

An immutable player identity. Offline profiles derive a stable UUID from the name, matching the convention used by other launchers.

Account offline = Account.offline("DevPlayer");
Account microsoft = new MicrosoftAuthenticator().signIn(clientId, System.out::println);
MemberDescription
Account.offline(String)Validates the name against [A-Za-z0-9_]{3,16} and throws IllegalArgumentException otherwise. The access token is 0 and the user type is legacy.
name, uuid, accessToken, xuid, clientId, userTypeIdentity fields passed to the game through launch placeholders.
isOffline()True for an offline profile.
label()Display name, with an offline suffix when applicable.

Never log, persist, or transmit accessToken. The desktop launcher redacts it from any echoed command.

MinecraftInstaller

Resolves official metadata, downloads and verifies every game file, and installs the declared Java runtime.

MinecraftInstaller installer = new MinecraftInstaller(Path.of("/games/ct"));
MinecraftInstaller.VersionCatalog catalog = installer.versionCatalog();
MinecraftInstaller.Installation installation = installer.install(catalog.latestRelease(), System.out::println);
MinecraftInstaller.Installation existing = installer.existing("1.20.4");
boolean installed = installer.isInstalled("1.20.4");
MemberDescription
MinecraftInstaller(Path gameDirectory)Stores the directory, absolute and normalized.
gameDirectory()The resolved game directory.
versionCatalog()Loads Mojang's current official manifest and returns every safe release, snapshot, special, and legacy version ID plus the latest release ID.
install(String version, Consumer<String> status)Full install: version metadata, client jar, rule-matched libraries, asset index, all assets, log configuration, natives directories, and the official Java runtime. Returns the resulting Installation. Throws IOException when metadata, verification, or the runtime fails.
existing(String version)Rebuilds an Installation from files already on disk, or returns null when the metadata, client jar, or runtime is missing.
isInstalled(String version)existing(version) != null.
VERSION_MANIFEST, JAVA_RUNTIME_MANIFESTThe official manifest URLs that the installer reads.

The Installation record

Installation is a record with gameDirectory, versionDirectory, librariesDirectory, assetsDirectory, nativesDirectory, clientJar, runtimeExecutable, logConfig, classpath, assetIndexId, versionId, and the parsed metadata. withRuntimeExecutable(Path) returns a copy that uses a different Java executable, which is how a host JVM override is applied.

Installation guarantees

Every install through MinecraftInstaller upholds six guarantees:

  • Checksum and size verification. Downloads with published SHA-1 and size are checked against both. Legacy library downloads without those fields are restricted to HTTPS and rejected if empty; published legacy checksums are still checked.
  • No partial installs. Downloads are written to a .part file and moved into place only after verification.
  • HTTPS-only, path-safe sources. Only HTTPS sources are accepted, and paths from official metadata are rejected when they escape their target directory.
  • HTTP/1.1 with retries. Transfers use HTTP/1.1 with up to four attempts and backoff, because the asset CDN resets concurrent HTTP/2 streams.
  • Safe native extraction. Platform-matched native classifiers are downloaded separately from classpath artifacts and safely extracted to the natives directory. Metadata exclusion paths are honored, and archive paths cannot escape the destination.
  • Verified runtime completion. The runtime is written under runtimes/<component>/<version>, executable bits are applied, symbolic links are validated against the runtime root, and .ct-runtime-complete is written only after the whole runtime verifies.

GameLauncher

Builds the argument list from the official metadata and starts the game.

GameLauncher launcher = new GameLauncher(installer.gameDirectory(), "2.2.0.1");
List<String> command = launcher.buildCommand(installation, account, options);
Process process = launcher.launch(installation, account, options, System.out::println);
int exitCode = process.waitFor();
MemberDescription
GameLauncher(Path gameDirectory, String launcherVersion)The version string is passed to the game as launcher_version.
buildCommand(Installation, Account, LaunchOptions)Returns the complete argument list. Supports modern argument arrays and legacy minecraftArguments, generates a missing classpath, and throws IOException for unsupported placeholders.
launch(...)Builds the command, appends game output to <game directory>/logs/ct-client-launch.log, forwards every line to the Consumer<String>, and returns the running Process.
LAUNCHER_BRANDct-client, passed to the game as launcher_name.

The command is runtimeExecutable, then the user JVM arguments, then the log configuration argument, then arguments.jvm, then the main class, then arguments.game. Rules are evaluated against the OS, architecture, and feature flags. An unknown placeholder such as ${unknown} is a hard failure instead of a silently dropped argument, so a metadata change surfaces immediately. The process starts through ProcessBuilder with the game directory as the working directory and no shell, so no argument is re-parsed or expanded.

RuleEvaluator

Evaluates Mojang rule objects. Used for library selection and for argument selection.

boolean allowed = RuleEvaluator.allows(libraryObject, RuleEvaluator.Features.none());
String os = RuleEvaluator.operatingSystem();
MemberDescription
allows(JsonObject element, Features features)An element without rules is allowed. Otherwise the last matching rule wins, and an element with no matching rule is denied.
operatingSystem()windows, osx, or linux, derived from os.name.
architecture()Raw os.arch value.
isArm(), is64Bit()Architecture predicates used for runtime and platform selection.
Features(demoUser, customResolution, quickPlaysSupport, quickPlaySingleplayer, quickPlayMultiplayer, quickPlayRealms)Feature flags matched against a rule's features object. Features.none() disables all of them.

MicrosoftAuthenticator

OAuth 2.0 device code sign-in, followed by the Xbox Live, XSTS, and Minecraft services exchanges, and a profile check that confirms the account owns Java Edition.

Account account = new MicrosoftAuthenticator().signIn(clientId, status -> System.out.println(status));

signIn(String clientId, Consumer<String> status) reports the user code and verification address through the consumer, opens the browser, polls for the token at the interval the service returns, and returns an Account with user type msa. Failures are reported as IOException with an actionable message, including the mapped XSTS cases such as a missing Xbox profile or a region restriction. The d= ticket prefix is applied only for the official launcher client ID; a third-party application sends its token unmodified.

The application must be a public client with the device code flow enabled, allowed to use the XboxLive.signin and offline_access scopes.

CT Loader mod API

CT's native mod interfaces live in com.ct.client.loader. CTMod is the entrypoint interface, CTModContext is handed to each entrypoint, CTModLoader scans mods/ and orders mods, and CTLoaderBootstrap runs in the game process before Minecraft's main class, passing the original game arguments through.

Each mod JAR carries a ct.mod.json at its root:

{
  "schemaVersion": 1,
  "id": "example",
  "name": "Example Mod",
  "version": "1.0.0",
  "entrypoints": ["example.ExampleMod"],
  "depends": []
}
InterfaceRole
CTModThe entrypoint interface. A public class with a public no-argument constructor implements it and receives the context in onInitialize.
CTModContextExposes the mod's parsed metadata, the game directory, the mods directory, and a mod-ID-prefixed logger through log.
CTModLoaderScans <game directory>/mods for JARs with a root-level ct.mod.json, checks required dependencies, rejects duplicate IDs and dependency cycles, and orders mods so dependencies initialize first.
CTLoaderBootstrapThe in-process bootstrap. It starts before Minecraft's official main class, initializes CT entrypoints in dependency order, then delegates to the game with the original arguments.

Dependency rules

  • Every ID in depends must be installed, or the launch stops with an error.
  • Duplicate mod IDs are rejected.
  • Dependency cycles are rejected — a cycle cannot be ordered.
  • Dependencies are initialized before the mods that depend on them.
  • A malformed mod or a failed entrypoint stops the launch with an error in the CT output.

The launcher's game classpath includes CT's application JAR, so the bootstrap and mod API are available in the game process. CT's own API provides initialization and logging only — it does not transform Minecraft classes or provide Minecraft lifecycle hooks, and it is separate from Fabric, Forge, and NeoForge APIs.
